NL SQL Agent — Detailed Architecture

HDFC distributor investor-search MVP. The Filter Catalog is the single source of truth for allowed filter values. It feeds every LLM system prompt, post-LLM sanitization, and validation — then deterministic code builds SQL (never LLM-generated SQL).

7. Catalog consumer matrix (complete)

ComponentFileHow catalog is used
Root agent instruction agent.py → filter_prompts.build_root_agent_instruction() At import: BASE + NOTICE + activity_duration list from catalog
Intent LLM prompt intent_detection._call_intent_llm() build_detect_intent_system_prompt() → catalog filter dimension reference
Search plan LLM prompt search_plan_builder._call_search_plan_llm() build_search_plan_system_prompt() → per-field allowed values + JSON schema
Post-LLM sanitization search_plan_builder._llm_output_to_search_plan() _allowed_values(filter_key) drops values not in catalog
Plan validation plan_validator.PlanValidator activity_duration, scheme_codes.allows()
Filter detection fallback filter_detection.message_has_search_filters() Uses PlanValidator.has_any_filter() on parsed plan (indirect)
CSV regression tests test_individual_csv_mapping.py Validates intent_parser + executor vs planning CSV (30 rows)
SQL execution individual_executor / non_individual_executor Does not read catalog — only trusted SearchPlan fields

9. Security & rules

  • LLM never generates SQL — only JSON filters constrained by catalog-backed prompts and sanitization.
  • Executors only run parameterized approved function/templates.
  • User never sees SQL, prompts, or query_arguments.
  • ARN from DEFAULT_DEV_ARN / session — not parsed from free text.
