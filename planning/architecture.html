3. Catalog SQL pipeline

sequenceDiagram
  autonumber
  participant T as generate_catalog_sql_query_tool
  participant R as query_flow_router
  participant M as module_router Haiku
  participant G as SQL generator Sonnet
  participant S as sql_guard
  participant V as validation_repair Haiku
  participant E as catalog_sql_executor
  participant DB as PostgreSQL

  T->>R: question + session_arn
  R->>M: select module ids
  M-->>R: core_arn_investor + …
  R->>G: slim guide JSON + question
  G-->>R: sql + parameters
  R->>S: sanitize · normalize
  T->>S: validate read-only · ARN-first %s
  alt guard fails
    T->>V: failed_sql + error
    V-->>T: corrected sql
    T->>S: re-validate
  end
  T->>E: execute_catalog_sql_readonly
  E->>DB: parameterized SELECT
  alt Postgres error
    T->>G: repair_context
    G-->>T: fixed sql
    T->>E: retry once
  end
  DB-->>T: rows · dedupe by uuid
  Note over T: session: final_query, last_sql, query_flow_trace

Guards: read-only, LIMIT ≤ 500, ARN first bind, no split name filters (normalized concat_ws + strip spaces), DISTINCT ON (i.uuid) for investor lists. Files: tools.py, query_flow_router.py, sql_guard.py, catalog_sql_executor.py.

Infra rows are order-of-magnitude for capacity planning (ap-south-1–style single app deployment), not invoices. At low volume, fixed infra can exceed LLM; above ~2k investor questions/month, Bedrock dominates. Legacy SearchPlan path was ~$0.02–0.05/question (Haiku-only, no Sonnet) — see appendix.
