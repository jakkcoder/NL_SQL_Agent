NL SQL Agent — Architecture

Distributor Individual investor chat: root Haiku routes each message; Sonnet (BEDROCK_QUERY_GENERATOR_MODEL_ID) reads filter_dp_investor_menu_catalog.json + the user question and returns a strict SELECT … FROM public.filter_dp_investor_menu(…) call (one automatic repair on failure). No base-table SQL. §6 is an optional offline catalog refresh; §7 is infra + LLM cost. See readme.md and planning/complete_function.sql.

Root agent does intent routing inline (no detect_intent_tool). Investor path: Sonnet receives function_contract + question; on generate/validate/execute failure it gets one retry with repair_context, then build_query_generation_failed_reply() if still failing. LLM unsupported_reason uses a different template (capability / future version) and does not retry.
