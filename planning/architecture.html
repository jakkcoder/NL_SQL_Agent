NL SQL Agent — Architecture (current)

HDFC distributor Individual investor chat MVP. Natural-language questions become read-only PostgreSQL via a modular schema guide and a large-context SQL generator LLM. Static guards validate SQL before execution; small LLMs handle module routing and validation repair.

3. Catalog SQL pipeline (detail)

Entry: generate_catalog_sql_query_tool(question) in app/agents/tools.py. Orchestrates generation in app/services/query_flow_router.py, guards in sql_guard.py, execution in catalog_sql_executor.py.

  Tool->>Router: run_catalog_sql_generator_llm(question, session_arn)
  Router->>ModR: select module ids (Haiku or keywords)
  ModR-->>Router: core_arn_investor + activity_transactions, …
  Router->>Gen: modular guide JSON + question
  Gen-->>Router: { thought, sql, parameters }

  alt validation fails
    Tool->>ValFix: validation_error + failed_sql

    Tool->>Router: repair_context (failed_sql, database_error)
    Router->>Gen: repair pass
    Tool->>Exec: retry once
  end

10. Security & product rules

  • ARN scope: DEFAULT_DEV_ARN / session — first %s bind; not parsed from user free text (arn_scope_guard).
  • Read-only SQL: Guards block DML/DDL; executor uses read-only connection settings.
  • LLM writes SQL in the catalog path (constrained by guide + guards + repair), unlike the legacy SearchPlan → fixed function path.
  • User-facing: Success shows result table + short summary; full SQL in session state (last_sql), not repeated in chat unless execution failed.
  • Non-individual and banking requests are refused without warehouse access.
