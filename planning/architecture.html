NL SQL Agent — Architecture

Distributor Individual investor chat: natural language → parameters for one warehouse function only — public.filter_dp_investor_menu (HDFC portal filters). No custom SQL on base tables. Unsupported asks get a standard capability reply. Six diagrams; §6 covers infrastructure + LLM cost. See readme.md and planning/complete_function.sql.

3. filter_dp_investor_menu pipeline (production)

sequenceDiagram
  autonumber
  participant T as generate_catalog_sql_query_tool
  participant H as investor_capability
  participant L as dp_investor_menu_llm
  participant B as dp_investor_menu
  participant DB as PostgreSQL

  T->>H: detect_unsupported_question
  alt city / age / scheme analytics / PAN…
    H-->>T: reason
    T-->>T: out_of_scope · no final_query
  else supported path
    T->>L: question + catalog JSON
    L-->>T: DpInvestorMenuParams JSON
    alt unsupported_reason set
      T-->>T: out_of_scope
    else
      T->>B: build_filter_dp_investor_menu_sql
      B-->>T: SELECT FROM filter_dp_investor_menu(...)
      T->>B: validate SQL shape + ARN bind
      T->>DB: execute (parameterized)
      DB-->>T: uuid, name, pan, dob, …
    end
  end
  Note over T: session: final_query.engine = filter_dp_investor_menu

Single RPC aligned with HDFC portal Individual tab and planning/complete_function.sql. SQL is always SELECT … FROM public.filter_dp_investor_menu(arncode, eligibility, otm, investortype, investorsubtype[], holding, systematic, activity, searchtext, sortkey, sortvalue, pagelimit, pageindex, allowbroker) — composites as PostgreSQL ROW(…)::current_holdings etc. Files: tools.py, dp_investor_menu.py, dp_investor_menu_llm.py, investor_capability.py. Mapping CSV: planning/Investor_Filter_Query_Mapping - Individual Investors.csv.
